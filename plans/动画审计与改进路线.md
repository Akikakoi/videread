## 三、v3 新发现的问题

### R1 index reduce 块漏 .ppick 浮层 【中·reduce 缺口】
分P 浮层 `.ppick.open` 用 dropIn 入场（304 行），但 374-385 的 reduce 块只关了 `.hist.open`——reduce 用户打开分P 选择器仍会播放入场动画。修法：reduce 块动画清单加 `.ppick.open`，一行。

### R2 JS 强制平滑滚动绕过 reduce 【中·reduce 缺口】
CSS `html{scroll-behavior:auto}` 管不住 JS `scrollIntoView({behavior:"smooth"})`：
- reader.js:89 章节导航/时间戳跳转硬编码 smooth——reduce 下点目录仍平滑滚动，长页尤其难受；
- index.js:413 目录点开特稿滚动到 feature 区，同样硬编码。
index.js:390 已有正确写法（matchMedia 判断 reduce → "auto"），抽一个小工具（或直接照抄判断）两处替换。grep 验收：JS 内不应再有裸 `behavior: "smooth"`。

### R3 reader.css 未 token 化 【低·一致性】
reader 全部 4 处 transition 是裸 `.25s ease`（.back / .theme-btn / .report-nav-link），与 index/job 的 `var(--t) var(--ease)`（.28s 自定义贝塞尔）页间切换有微差。reader 本身无 :root --ease/--t 行，需补令牌或明确接受 .25s 差异并记录。job.css `#toast.out` 的 `animation:toastOut .28s` 裸时长同类（index 也裸，两页一致，可不动）。

### R4 跨页重复定义 【低·维护性】
markPop / toastIn / toastOut / dropIn 四组 keyframes 在 index.css 与 job.css 各一份；stepperSeen 增量弹入逻辑 index.js 与 job.js 各一份。theme.js 已有三页共享先例——可选抽 `css/shared.css`（令牌+keyframes+reduce 块）与 `js/stepper.js`。代价是多一个请求且破坏「按页拆分」的 P1 决策，本机单人场景收益有限，可不做，记录即可。

### R5 theme-switching 250ms 截断 【低·边缘】
theme.js 切主题后 250ms 移除禁过渡类，而最长过渡是 reveal 的 --t-slow=.8s——若切换瞬间恰有 reveal 在播会被截断加速。实际主题切换影响的主是颜色类 --t=.28s 过渡，差 30ms 几乎不可感；要修就把 250 改 850。

### R6 新来信无入场动画 【低·一致性，v2 遗留】
真实路径 ask() 拿到回信后 `list.innerHTML = history.map(renderLetter)` 全量重绘，新信突现；历史回放不重播动画是对的，但新插入项应有一次性的 dropIn/淡入（参照 stepper 增量 pop 思路：给最后一封或第一封加一次性类）。

### R7 持续原则（非问题）
- reduce 模式下新增动画一律静止，验收时三页手动过一遍；
- 一切出现皆有过渡的新基调延续（jobline/probeline 内容 swap 目前无动画，属信息行，可接受）；
- 模板三件维持自包含与独立配色，ts-jump hover 白底硬编码无害（报告无深色主题）。
